# 功能 7：AI 员工

你手上本来就有一些 AI：能联网搜索的、能生图生视频的、会写会挑毛病的。工作台按它们各自擅长什么，自己给它们安排活。总台（你正在用的这个 Agent）是老板：派活、收活、核实，核实完才给你。

## 1. 分岗

起步五个岗，按你手上有什么 AI 来配。一个 AI 可以兼好几个岗；没有合适的，这个岗总台自己做。

| 岗位 | 干什么 | 适合什么 AI | 什么时候派 | 交什么 |
| --- | --- | --- | --- | --- |
| 雷达 | 去网上找最新的热点，尤其是海外刚起量的工具和话题 | 能实时联网搜索、能看社交平台的（例：Grok 一类） | 每天今日热点时 | 3–5 条：是什么、什么时候开始火、原帖链接、官方出处 |
| 踩点 | 录之前先把步骤和容易踩的坑查清楚 | 能联网、会查文档的 | 选题定了、录之前 | 入口在哪、几步、哪步容易错、要不要付费、国内能不能用，都带出处 |
| 挑刺 | 挑稿子和标题的毛病 | 会写、有判断力的大模型 | 稿子写完、交给用户前 | 最该改的 3 处，每处说为什么、怎么改 |
| 红线 | 看这条内容能不能发、有没有风险 | 能联网查新闻和平台规则的 | 发布前 | 涉及的人、公司、事件、说法，每项判「能发 / 小心 / 别发」，带出处 |
| 画面 | 剪辑缺画面时生成素材 | 能生图、生视频的 | 剪辑时缺镜头 | 按镜头单出画面，每个镜头 2 版，自己先看有没有穿帮 |

写进 `00-总台/员工/岗位表.md`（模板就在那），每个岗位再写清：**不擅长什么**（例：生视频的不擅长人物特写、多镜头同一个人），免费额度多少、要不要花钱。

## 2. 怎么连上

这个 Skill 不带任何现成的接入程序，按你的工具选：

| 你的 AI 有什么 | 怎么派活 |
| --- | --- |
| 有 API | 总台写个小脚本调用（密钥放环境变量），派活单当输入，交付存进 `00-总台/员工/交付/` |
| 只有网页 / App | 总台把派活单写好，你复制过去，把回答贴回来；或者 Agent 有浏览器操作能力、你允许的话，让它代你操作 |
| 在同一个 Agent 里有子助手 | 直接派给子助手，按同样的派活单 |

接入方式写进岗位表的「通道」一列。**花钱的（按次计费的 API、生图生视频额度）先报价**，只用免费额度就写清楚。

## 3. 派活

复制 `00-总台/模板/派活单.md`，填：给哪个岗位、目的、背景（附要看的文件或链接）、要交什么、什么格式、多久交、怎么算合格。

在 `00-总台/员工/任务记录.md` 加一行：日期、岗位、任务、状态「已派」。

**派完不要干等**：接着做自己的活，过一会儿再收。

## 4. 收活：总台先核实

收回来的东西，交给用户之前总台必须做完这几件：

1. **核实出处**：每条至少打开一个原始出处，看原话对不对得上。对不上、打不开、没出处的，不用。
2. **和自己做的比**：同一件事总台自己也做一遍（或者已经做了），用好的那个，不如的不用。
3. **按原标准再过一遍**：热点照选题三关（过了 5 天不要），稿子毛病照纠正记录判断该不该改。
4. **改好再给**：用户看到的是总台核实、改好之后的东西。**出了错算总台的**，不能说「是员工给的」。
5. **验收记录**：任务记录那一行写「通过 / 返工 / 放弃」，加一句用了哪几条、为什么没用。

交得不合格（没链接、编的、格式不全）可以返工一次，写清哪里不行。

## 5. 员工保底

员工只做加法，不能因为加了员工让产出变差：

- 员工不在线、报错、超时、交得不合格 → **跳过员工，照原来的流程做完**，产出不能少、不能慢。
- 产出文件里写一句「员工没用上：原因」。
- 原来每一步检查都照做，不因为「员工查过了」就跳过。

## 6. 每周看贡献

周报里每个岗位写一行：这周派了几件、用上几件、用上的东西发出去后数据怎么样，有没有拖慢或帮倒忙。

- 连续两周没有用上的，调整岗位说明，或者撤掉这个岗。
- 一直好用的，可以多派一类活。
- 调整写进 `00-总台/成长/待升级.md`，用户同意再改（功能 8）。

## 员工的提示词放哪

每个岗位的具体提示词、交付格式细节，写进 `00-总台/员工/岗位表.md` 下面各岗的「岗位说明」。这里只给岗位和规矩，具体怎么说，按你用的 AI 自己写、自己调。
