# aningneo-workbench：搭一个 AI 运营团队

一个人做号，选题、写稿、剪辑、看数据全是自己来，很累。这个 Skill 帮你在本地搭一个工作台：它更像一个运营团队，员工都是 AI。你平时只做两件事——看到好选题丢给它，把口播录好。

搭好以后，它每天能替你做这 8 件事：

| # | 功能 | 它做什么 | 细节 |
| --- | --- | --- | --- |
| 1 | 选题 | 每天定时刷多平台热点，从一大堆里留下几个，写清为什么会火、从哪个角度讲、打分；火了超过 5 天的不选 | `references/01-选题.md` |
| 2 | 写稿 | 自己定明天发哪条，写好口播稿、标题、封面字、评论区第一条 | `references/02-写稿.md` |
| 3 | 知识库 | 记住你是谁、怎么说话；每纠正一次记一条，下次写稿先查；碰到你没用过的工具先问你 | `references/03-知识库与纠正.md` |
| 4 | 每天复盘 | 你定一个目标，它定时看粉丝数，每天早上出晨报：离目标差多少、哪条涨粉哪条没人看、下一条怎么改、今天先做哪几件 | `references/04-复盘与晨报.md` |
| 5 | 商单排期 | 一单好几期，每期哪天录、哪天交审、哪天发都排进日程，同步到日历；记住竞品期 | `references/05-商单与日历.md` |
| 6 | 剪辑 | 照着稿子剪口播，剪完自己检查字幕和声音，有问题自己改，再拿给你看 | `references/06-剪辑与自检.md` |
| 7 | AI 员工 | 把你手上已有的其他 AI 按长处分岗，总台派活、核实后再给你 | `references/07-AI员工.md` |
| 8 | 自己学习 | 每周固定一天上网学运营方法，另一天整理成建议，你同意了才改规则 | `references/08-每周学习.md` |

第一次搭、怎么设定时任务，看 `references/00-搭建.md` 和 `references/定时任务.md`。

| 用户说 | 做什么 |
| --- | --- |

| 「晨报」「今天做什么」「复盘」「这条为什么没流量」 | 功能 4 |
| 发来商单 Brief、说「排一下商单」「同步日历」 | 功能 5 |
| 发来口播原片、说「剪」「审一下这个片子」 | 功能 6 |
| 「给员工派活」「让 XX 去查」「员工这周干得怎么样」 | 功能 7 |

一次说了好几件，按上表顺序一件一件做，每件做完说一句结果。

## 第一次搭

按顺序来，每一步做完再进下一步。完整说明在 `references/00-搭建.md`。

1. **问清 6 件事**（已经知道的不再问）：账号名和平台；做什么内容、给谁看；现在多少粉、想多久涨到多少；你手上有哪些 AI 和工具（能联网的、能生图生视频的、剪辑软件）；用哪个 Agent（Claude Code / Codex / WorkBuddy）；工作台放在哪个文件夹。
2. **先预览再建**：

   ```bash
   python3 <skill目录>/scripts/init_workbench.py --root <工作台文件夹> --name "<账号名>"
   ```

   默认只打印要建哪些文件，不写。用户看过说可以，再加 `--apply`。已有的文件一个都不覆盖。用 Claude Code 的加 `--agent claude-code`（会多建一个 `CLAUDE.md`，里面只有一行 `@AGENTS.md`）。
3. **填「我是谁」**：把第 1 步问到的写进 `01-我/我是谁.md`、`01-我/账号定位.md`，目标写进 `05-选题与排期/目标.md`。没问到的留着空，写【待补充】，不编。
4. **填说话卡**：请用户贴 3–5 段自己以前的口播稿或录音转写，原样放进 `01-我/说话卡.md` 的「原话样本」。没有就先空着，写稿时会靠纠正记录慢慢长出来。
5. **登记工具和员工**：用户用过的工具写进 `01-我/我用过的工具.md`；其他 AI 按长处写进 `00-总台/员工/岗位表.md`（见功能 7）。
6. **设定时任务**：照 `references/定时任务.md`，按用户用的 Agent 给出能直接复制的设置。设之前把每个任务花不花钱说清楚。
7. **体检**：跑 `python3 <skill目录>/scripts/check_workbench.py --root <工作台文件夹>`，有红色问题就修。
8. **交付**：告诉用户建了什么、明天早上几点会看到什么、现在可以先说哪一句话试一下（例如「今日热点」）。

## 工作台长什么样

```text
工作台/
  AGENTS.md              总台规则：Agent 每次开工先读
  00-总台/               晨报、周报、收件箱、员工、成长（纠正记录、待升级、效果账本）、定时任务、授权、模板
  01-我/                 我是谁、说话卡、账号定位、我用过的工具
  02-方法/               写稿手册、选题标准、剪辑自检表、钩子库（都是起步版，跑起来再长）
  03-调研/               热点（每天一个文件夹）、学习资料
  04-作品/编号_日期_短标题/   文稿、素材、剪辑、成片
  05-选题与排期/          目标、选题池、日程表、内容总表、商单
  06-复盘/               粉丝记录、数据
```

路径一律相对工作台根目录。模板在 `00-总台/模板/`，要用时复制一份再填。

## 每天、每周自动跑什么

| 时间（可改） | 任务 | 用到的功能 |
| --- | --- | --- |
| 每天 07:30 | 今日热点：刷热点、挑题、打分，锁定明天发哪条并写好稿 | 1、2、7 |
| 每天 08:30 | 晨报：看粉丝数和数据，出今天的晨报 | 4 |
| 按你定的频率 | 记粉丝数（免费：一天一次；付费接口：先算清一天多少钱） | 4 |
| 每周一 09:00 | 运营周报：上周复盘、目标对账、下周排进日程 | 4、5 |
| 每周三 21:00 | 运营学习：上网学最新运营方法 | 8 |
| 每周日 21:00 | 整理升级建议，等你点头 | 8 |

提示词开头是「【定时任务·…】」的，就是没人在旁边看着跑的：**不要问问题**，要用户决定的写进晨报、周报或待升级，等他下次打开看。

## 八个功能怎么做（摘要）

每个功能的完整步骤、模板和检查表在对应的 references 里。做哪件事就读哪份，不要一开场全读。

### 1. 选题

1. 先读 `02-方法/选题标准.md`、`01-我/账号定位.md`、`01-我/我用过的工具.md`、`05-选题与排期/选题池.md`（别重复）。
2. 刷多个平台的热点，全部记进 `03-调研/热点/<今天>/候选.md`，写清每个平台抓了几条。免费路线用网页搜索和公开热榜；付费接口先报价（见「花钱和密钥」）。
3. 过三关：**利他**（观众看完能拿走什么，答不出直接扔）→ **新鲜度**（72 小时内起量、还在出新作品 = 上升；起量超过 5 天 = 过气，再火也不选）→ **对口**（落在账号的线上；用户没用过的工具不直接排，先问）。
4. 留 3–6 个，每个写：为什么会火（带数据和链接）、从哪个角度讲、预测分（满分 10）、星级、要准备什么。用 `00-总台/模板/今日热点.md`。
5. ★4 以上的进选题池。

### 2. 写稿

1. 看日程表明天那一格：写着「已定」或是商单日的不动；写着「暂定 / 热点位」的，拿暂定题和今天的热点比，留下更能带播放和粉的，改成「已定：<标题>」。
2. 写稿前先读：`01-我/我是谁.md`、`01-我/说话卡.md`、`00-总台/成长/纠正记录.md` 里同场景的条目、`00-总台/成长/效果账本.md`、`02-方法/写稿手册.md`。
3. 建 `04-作品/D编号_日期_短标题/`，用 `00-总台/模板/发布包.md` 写：口播稿（带【画面】提示）、3 个标题、封面字、评论区第一条、发布简介。
4. 交稿前照写稿手册的自检表过一遍。改版就在原文件上改，旧版另存 `_旧`，不另起新文件名。

### 3. 知识库与纠正

- 用户每改一次稿、每说一次「不对」，**当场**在 `00-总台/成长/纠正记录.md` 追加一条：场景、AI 写的、用户要的、以后怎么做、类别、这类第几次。不用问。
- 同一类到第 3 次，在 `00-总台/成长/待升级.md` 写一条建议，把它变成固定规则。
- 写稿、选题之前先查同场景的纠正。
- 题里有 `01-我/我用过的工具.md` 里没有的工具，先问用户认不认识、要不要做，不直接排进日程。

### 4. 每天复盘与晨报

1. 读 `05-选题与排期/目标.md`、`06-复盘/粉丝记录.md`、`00-总台/成长/效果账本.md`、内容总表、日程表。
2. 补到期的数据：发布满 24 小时、满 7 天的作品各记一次。
3. 写 `00-总台/晨报/<今天>.md`（模板 `00-总台/模板/晨报.md`）：离目标差多少、哪条涨粉哪条没人看（和自己的中位数比）、下一条怎么改（3 条，带依据）、今天先做的 3 件、每条内容到哪了、明天发什么。
4. 对话里只回晨报路径和「今天先做这 3 件」。

### 5. 商单排期

1. Brief 进 `05-选题与排期/商单/<日期_这单>/`，用 `00-总台/模板/商单.md` 列每一期：录制、交审、修改、发布日期，品牌红线。
2. 每个节点写进 `05-选题与排期/日程表.md`；发布日起 N 天（Brief 写的，没写就问）加一行「竞品期」。新商单进来先查有没有撞竞品期。
3. 同步日历：系统日历跑 `scripts/schedule_to_ics.py` 生成 `.ics` 导入或订阅；飞书等在线日历走用户自己配的接口（见 references）。改了日程表就再同步一次。
4. 做没做完以用户说的为准，过了时间没确认的，在晨报里问一句。

### 6. 剪辑与自检

1. 收齐：口播原片、`文稿/发布包.md` 里的口播稿、专有名词。口播稿就是字幕的标准答案。
2. 粗剪：`scripts/rough_cut.py` 按停顿切（默认只预览切点）；口误重说的只留最后一遍。
3. 字幕：转写（本地免费的 Whisper 类工具，或付费接口先报价）→ 对着口播稿改 → 跑 `scripts/subtitle_check.py` 找对不上的句子。
4. 画面：照口播稿【画面】补录屏和 B-roll；缺的派画面员工补（功能 7）。在剪映、Remotion 或 ffmpeg 里合成，先出 720p 预览。
5. 自检：跑 `scripts/check_video.py`（响度、静音、黑场、首帧和抽帧），再照 `02-方法/剪辑自检表.md` 过一遍。**必须改的自己改完再检**，然后把预览和自检报告一起给用户。
6. 用户点头才出成片。

### 7. AI 员工

1. `00-总台/员工/岗位表.md` 里每个岗位写：用哪个 AI、擅长什么、不擅长什么、什么时候派、交什么、怎么验收。起步五个岗：找热点、录前踩点、挑毛病、看风险、补画面。
2. 派活用 `00-总台/模板/派活单.md`，在 `00-总台/员工/任务记录.md` 记一行。
3. 收回来**总台先核实**：每条至少打开一个原始出处对原话；和总台自己做的比，用好的那个；编的、过期的、没出处的不用。核实完、改好了才给用户，出了错算总台的。
4. **员工保底**：员工不在线、超时、交得不合格，就跳过员工，按原流程做完，不能因为员工让产出变少变慢。
5. 每周周报里写每个岗位派了几件、用上几件。连续两周没用上的，调整岗位说明或撤掉。

### 8. 每周学习

1. 周三：上网查最近一两周的平台运营方法和规则变化，只收有出处的 3–5 条，存 `03-调研/学习资料/<日期>_运营学习/要点.md`（模板 `00-总台/模板/学习要点.md`）。
2. 周日：把这周的纠正记录、效果账本和学到的东西，整理成建议写进 `00-总台/成长/待升级.md`，状态「待定」。
3. 用户说「同意第 N 条」才改对应的规则文件，改完把状态改成「已采纳」并写清改了哪。用户说不要的写「不采纳」和原因。

## 规矩

- **先预览再写**：建骨架、批量改文件之前先给用户看清单。用户的原文件只读，产出另存。删除、覆盖、移动已有文件先问。
- **花钱先报价**：抓数据、生图生视频、语音转写这类按次收费的接口，开跑前说清要发多少次、大概多少钱，用户同意再跑。用户给了长期授权（比如「每天 5 次以内直接抓」）就写进 `00-总台/授权.md`，超出就停下来问。
- **密钥不进工作台的文本、不进仓库、不外发**：放环境变量或系统钥匙串，只记「在哪」。
- **只写真的**：数据只用平台抓的或用户给的；没有的经历和数字写【待补充】。AI 的判断写清是建议。
- **对外的事都先问**：发布、发消息给别人、登录账号、付费，都等用户点头。
- **原创优先**：别人的爆款只借选题和结构，内容用用户自己的经历、实测和观点。
- **用中文和用户说话**，结论先说，要选的时候列 1、2、3。

## 起步版和定制版

这个 Skill 给的是骨架、流程、模板、检查表和起步规则，照着做就能跑起来、写出稿子、剪出片子。下面这些故意留空，因为每个账号都不一样，要靠你自己跑出来：

- 你的说话卡、钩子库、爆款规律、封面风格：跑一段时间后，由纠正记录和效果账本长出来。
- 剪辑风格、动效、配乐、模板：照你自己喜欢的片子慢慢定，写进 `02-方法/剪辑自检表.md` 后面。
- 员工的具体提示词、网页看板：按你手上的工具自己写。

想按自己的账号把整套定制好（网页工作台、剪辑风格、员工接入等），可以在仓库提 Issue 联系作者。
